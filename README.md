# 教育智能体项目

> **通用 AI 的失败模式都是「看起来对」。**
> 我们把 LLM 限制在**理解与澄清**，把**正确**交给确定性引擎。

- **阅读模块**：LLM 理解学习者的困惑 → 状态机保证学习轨迹可信
- **物理模块**：LLM 抽取题目参数 → 解析解保证物理正确

两个模块共享同一套骨架：对话、澄清协议、工具调用、记忆层。

---

## 0. 三分钟看懂

一个 **agent**，不是"调一次模型就返回"。每一轮对话都是一次循环：

```
用户输入
   ↓
组装上下文（系统提示词 + 相关记忆片段 + 输入）
   ↓
┌─→ 模型思考（reasoning）
│      ↓
│   要调工具吗？
│   ├─ 是 → 执行工具（由代码校验）→ 把结果喂回 → 回到"模型思考"
│   └─ 否 → 输出最终回复，结束
└───（最多 max_steps 次）
```

**这个循环存在的唯一目的：让模型只能"提议"，不能"决定"。**

## 1. 架构

### 分层

```
┌──────────────────────────────────────────┐
│ 前端：门户 / read/ / physics/             │  纯静态 HTML
└────────────────┬─────────────────────────┘
                 │ HTTP  /api/...
┌────────────────▼─────────────────────────┐
│ backend/core/   共用骨架（只写一次）       │
│   对话循环 · 工具执行 · 记忆 · 设置 · 追踪 │
└────────────────┬─────────────────────────┘
                 │ 五个接口（合约）
┌────────────────▼─────────────────────────┐
│ backend/domains/read/   backend/domains/physics/ │
│   提示词 · 状态机        SceneSpec · 解析解       │
└──────────────────────────────────────────┘
```

### Agent 的六个要件

| 要件 | 位置 | 现状 |
|---|---|---|
| Agent 循环 | `core/agent.py` | ⏳ 待实现 |
| 工具调用 | `core/tools.py` + `domains/*/tools.py` | ⏳ 只有注册表骨架 |
| 思考链 | `core/trace.py` | ⏳ 待实现（只存档，不显示给用户） |
| 记忆 | `core/memory.py` | ⏳ 待实现（快照 + 事件流） |
| AI 设置 | `core/settings.py` | ⏳ 待实现（模型/温度/effort/步数） |
| 可观测 | `core/trace.py` | ⏳ 待实现（答辩时能现场展示"它想了什么"） |

### ★ 最关键的一条设计

**状态只能通过工具修改，绝不能让模型直接输出结论。**

```python
# 模型只能"请求"改状态
update_concept_status(term, target, self_explain_score, used_hint)
#   → 内部调 engine.transition()
#   → 非法转移（如 unresolved 直接跳 mastered）返回 ok: false
```

模型想跳过一步，代码直接拒绝。**这是整个产品可信度的来源。**

工具白名单也要分领域：read 的会话不该能调 physics 的工具。

## 2. 目录与领地

**一个人 = 一个文件夹。只改自己的文件夹，就不会冲突。**

| 路径 | 负责人 | 内容 |
|---|---|---|
| `backend/core/` | 骨架负责人 | 对话循环、工具、记忆、设置、追踪 |
| `backend/domains/read/` | 阅读负责人 | 概念卡、状态机、提示词 |
| `backend/domains/physics/` | 物理负责人 | SceneSpec、解析解、校验 |
| `frontend/index.html` `theme.css` `blocks.js` | 门户负责人 | 门户、设计变量、通用渲染器（**全员共用**） |
| `frontend/read/` | 阅读负责人 | 阅读工作台 |
| `frontend/physics/` | 物理负责人 | 物理工作台 |
| `tests/` `docs/` | 内容/测试 | 用例、文档、PPT |
| `data/examples/` | **全员共同维护** | 数据样例（合同） |

---

## 3. 五条铁律

1. **`core/` 只有一个主人。** 谁都能提需求，只有他能改。
2. **领域之间不许互相引用。** `read/` 不能 import `physics/`。
3. **接口冻结后才能并行。** 见 `docs/interface.md`。
4. **配置不进代码。** key、端口、路径全部走 `.env`。
5. **`main` 永远能跑。** 跑不起来的东西不许合并。

## 4. 接口与数据契约

| 文件 | 作用 |
|---|---|
| `docs/interface.md` | 五个函数的签名、`to_view` 的 block 规范 —— **v1.0 已冻结** |
| `data/examples/read_concept_card.json` | 概念卡长什么样 |
| `data/examples/physics_scene_spec.json` | SceneSpec 长什么样 |

**这三个文件是合同，改它们必须全员同意。**

## 5. 怎么跑

```bash
# 1. 装依赖（需要联网）
uv sync                      # 或 pip install -r requirements.txt

# 2. 配置
cp .env.example .env
# 编辑 .env，填入 DEEPSEEK_API_KEY

# 3. 启动
uvicorn backend.app:app --reload --host 0.0.0.0 --port 8000

# 4. 打开
# http://localhost:8000/          门户
# http://localhost:8000/read/     阅读模块
# http://localhost:8000/physics/  物理模块
```

**前端是纯静态 HTML，双击 `frontend/index.html` 也能直接看界面**（没有后端时会用内置 demo 数据兜底）。

跑阅读状态机的测试：

```bash
uv run python tests/test_read_state.py
```

卡超过半天就在群里喊人。设计项目最常见的死法不是做不出来，是一个人默默卡了三天。

## 7. ★ 给 AI 助手的工作须知

### 7.1 开工前，先贴这段给你的 AI

把下面整段复制给它（每个组员每次开工都贴一次）：

```
你正在协助开发一个教育智能体项目，仓库根目录是 agentproject/。

开工前请先读这四个文件，读完再动手：
  1. README.md              —— 项目约定与分工
  2. docs/interface.md      —— 五个接口的合同（已冻结）
  3. data/examples/*.json   —— 数据结构样例（合同）
  4. 你要改的那个文件夹里的所有文件

【硬性禁止】
- 不许改 docs/interface.md 和 data/examples/ 里的任何内容
- 不许改你负责范围以外的文件夹
- 不许在代码里写死 API key、绝对路径、localhost 地址
- 不许引入新的第三方依赖（先问）
- 不许把状态更新写成"模型输出文本后解析"，必须走工具调用
- 不许删除已有的 TODO 注释而不实现它

【必须遵守】
- 所有配置从 backend/config.py 读，不要自己 os.getenv
- 前端请求一律用相对路径 /api/...，不要写 http://
- 新增的数据字段，必须同时更新 data/examples/ 里的样例
- 中文注释，术语给英文对照
- 一次只改一个文件或一个函数，改完说清楚改了什么

【交付前自检】
- 这段代码跑得起来吗？怎么验证？
- 我改的东西有没有碰到别人的文件夹？
- 有没有破坏 docs/interface.md 里定义的签名？
```

### 7.2 交付时，用这个模板在群里说

```
【模块】read / physics / core / frontend
【改了什么】一句话
【改了哪些文件】
【怎么验证】具体命令或点击路径
【有没有用到别人还没做的部分】是/否 + 是什么
【卡在哪】没有就写"无"
```

最后一行最重要。**没写"卡在哪"的，默认没有卡。**

### 7.3 为什么这么做

五个人用五个不同的 AI。如果不给它们同一份约束，它们会写出五套风格、五种接口、五个 `localhost`。

**读同一份 README，产出的代码才拼得起来。**

## 9. 术语表

| 术语 | 意思 |
|---|---|
| **agent 循环** | 模型 → 调工具 → 看结果 → 再想，直到不需要工具 |
| **工具（tool）** | 模型可以请求调用的函数，参数和结果由代码控制 |
| **SceneSpec** | 物理场景的结构化中间表示（JSON） |
| **IR（中间表示）** | 把自然语言变成结构化数据，再交给确定性逻辑处理 |
| **状态机** | 概念卡的状态流转：`unresolved → shaky → mastered` |
| **consolidate（结账）** | 会话结束时，把这一节的记忆压缩成快照 |
| **block** | 前端渲染的最小单元（header/text/quote/chips/buttons/steps/table/canvas/card） |
| **白名单** | 只允许模型调用指定的几个工具 |
